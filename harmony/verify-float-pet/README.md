# 77 Pet 鸿蒙版

在 HarmonyOS PC / 2in1 桌面上显示一只可拖拽、可点击、会碎碎念的桌面宠物。

鸿蒙的系统壁纸层不向第三方开放，所以这里不是替换壁纸，而是用
`TYPE_FLOAT` 全局悬浮窗把宠物放到桌面上。视觉上就是一只没有窗口边框、
没有背景卡片的透明宠物。

## 跑起来

前置条件：

- DevEco Studio 6.1.1 或更新版本
- HarmonyOS PC / 2in1 SDK
- 已启动的 2in1 模拟器或真机
- 宠物资源目录默认在 `~/Desktop/workspace/77-pet-packs`

```bash
./run.sh assets    # 从 77-pet-packs 生成轮廓、动画配置和素材
./run.sh build     # 编译
./run.sh install   # 安装到设备
./run.sh start     # 重启应用
./run.sh log       # 看 Pet77 日志
./run.sh shot      # 截图到 /tmp/pet-shot.jpeg
./run.sh all       # 以上全部执行
```

如果宠物包放在别处：

```bash
PET_PACKS_ROOT=/path/to/77-pet-packs ./run.sh assets
```

第一次启动会出现在桌面右下角。之后会恢复上次退出时的位置。

## 怎么用

- 单击宠物：随机点击回应。
- 按住拖动：抓起宠物；快速甩动松手会抛出去，碰到屏幕边缘会反弹。
- 长按宠物：打开菜单。
- 鼠标右键：同样打开菜单。
- 菜单里可以按分类点播动作、叫它一声、回到右下角、打开设置或退出。
- 点头顶气泡：收起这句话。

设置里的改动即时生效，不需要点保存：

- **宠物**：切换已打包的宠物种类。
- **大小**：60% 到 140%。
- **不透明度**：30% 到 100%。
- **走动的频率**：0 表示一直待在原地。
- **碎碎念**：按间隔随机说话，带宠物包自带表情包。
- **稳定待机**：静止时定格，点击、拖拽、菜单动作仍正常播放。PC 模拟器默认开启，
  真机默认关闭。旧版本可能把测试时的关闭值留在模拟器里，本版升级后会一次性纠正为开启；
  之后仍可在设置里手动切换。
- **AI 碎碎念**：填 OpenAI 兼容接口、模型和 API Key 后，由模型生成一句话。

AI 相关说明：

- 接口地址填到 `/v1` 即可，例如 `https://api.openai.com/v1`。
- 也支持本地兼容服务，例如 `http://127.0.0.1:11434/v1`。
- 未开启 AI、未填 Key、网络失败、接口返回异常，都会静默回落到宠物包自带文案。
- API Key 只保存在本机应用数据里。

## 宠物包

素材目录：

```text
entry/src/main/resources/rawfile/pet/
  packs.json
  packs/
    blue-maid/
      anim-config.json
      alpha-masks.json
      preview.png
      webm/*.webm
      memes/*.png
    kunkun-chick/
      ...
```

`./run.sh assets` 会扫描 `77-pet-packs/pets/*`，对每个包含
`config.jsonc` 和 `webm/` 的包执行：

1. 用 ffmpeg 量出每段动画的 alpha 轮廓。
2. 生成运行时动画配置。
3. 复制 WebM 和表情包。
4. 生成设置页使用的 `packs.json`。

新增宠物包时，不需要改页面代码，重新执行 `./run.sh assets` 后就会出现在设置里。

## 为什么这样做

### 双窗口：画面和点击分开

`TYPE_FLOAT` 默认会带一层系统材质：整窗半透明提亮、圆角和阴影。把背景设为透明、
阴影和圆角设为 0，就能得到干净的透明画面。

但只这样做的话，整个矩形窗口仍然会拦截鼠标。最初的方案是用 `setWindowMask`
把窗口裁成宠物轮廓（遮罩同时决定显示和点击区域），实测每换一次动画都会让系统
重新合成整个桌面，**整屏黑一帧**，表现为疯狂闪烁。改成固定并集遮罩后不再闪，
但并集覆盖了窗口 92% 的面积，透明处几乎都点不穿。

现在的做法是拆成两个窗口：

1. `pet77_float`：384x396 的透明画面窗，只负责显示，`setWindowTouchable(false)`
   彻底不接鼠标，也不设置任何窗口形状；
2. `pet77_hit`：240x396 的透明点击窗，贴在宠物身体和气泡那一竖条上，接住点击、
   拖拽和右键，再通过内存队列转给画面窗。

移动、缩放、丢出时两个窗口一起走。点击窗是普通透明窗，同样不设窗口形状，
所以动画切换、漫游、拖拽全程都不会再触发整屏重合成。

代价是点击窗左右各 72 像素（逻辑尺寸）不拦截鼠标，这两条透明边可以直接点到桌面；
头顶气泡区在气泡没显示时也不会触发宠物动作，但仍属于点击窗范围。

### 不用转码

ArkWeb 内核能直接播放 VP9 + alpha 的 WebM，`77-pet-packs` 里的原素材可以直接用。
试过 WebP 动图和 APNG，体积分别约为原视频的 5 倍和 31 倍，代价不值得。

### 气泡

气泡画在窗口顶部的预留区里，不参与任何窗口形状计算。页面把气泡矩形报给 ArkTS，
点击时用这个矩形判断是「点气泡收起」还是「点宠物回应」。

### 模拟器闪屏与稳定待机

PC 模拟器在持续刷新透明悬浮窗时，宿主的 `express_gpu_render` 合成层会偶发整屏黑帧。
窗口截图能直接录到：不播放动画时 20 秒 0 次，持续播放时 10 秒约 10 次，只有模拟器
侧边栏保持正常。这是模拟器的 GPU 合成问题，不是 ArkUI 页面或透明视频本身出错。

应用因此在模拟器上默认开启「稳定待机」：待机视频播到首帧后暂停，主机不再持续合成；
点击、拖拽、菜单点播、碎碎念等主动交互仍会正常播放。真机默认关闭，保持完整待机动画。
这个开关在设置 → 行为 → 稳定待机里，可随时切换。

旧版测试过程中若把它关掉，关闭值会被 Preferences 保存，覆盖“模拟器默认开启”的默认值，
导致升级后仍然闪烁。本版用单独的一次性迁移标记兼容这个情况：模拟器升级后强制恢复开启，
后续用户主动关闭不会被再次覆盖。

### API 24 兼容

当前 PC 模拟器是 API 24：

- `setWindowTouchable`、`setWindowFocusable` 可用，双窗口方案只依赖这些基础接口。
- `setTouchableAreas`、`setWindowMaskWithAlpha` 等 API 26 接口不可用。
- `setWindowMask` 在 API 24 可用，但会触发整屏重合成，已完全不再调用。

## 打包与真机

```bash
./run.sh release
```

产物：

```text
dist/pet77-<版本号>-unsigned.hap
```

`SYSTEM_FLOAT_WINDOW` 是 ACL 受限权限。模拟器和已配置调试签名的设备可以直接安装；
朋友的真机需要：

1. 把设备 UDID 加入 AGC 调试设备列表。
2. 生成包含 `SYSTEM_FLOAT_WINDOW` 的调试 Profile。
3. 在 DevEco Studio 的 `build-profile.json5` 里配置签名后重新打包。

没有签名配置时 `./run.sh release` 只产出未签名 HAP。

## 已知限制

- 只支持 HarmonyOS PC / 2in1；手机和平板没有可用的全局悬浮窗路径。
- 第三方不能替换系统壁纸层，这是鸿蒙平台限制。
- 当前宠物包随 HAP 一起打包，还没有做“从网络下载宠物包 / 导入 zip”。
- 还没有系统托盘和开机自启。
- 多显示器目前只按主屏工作区定位。
- AI 请求需要用户自备兼容接口和 Key。

## 验证记录

已在 MateBook Pro 2in1 模拟器（API 24）实际验证：

- 稳定待机开启后连续录屏 20 秒：622 帧，暗帧 0 次，模拟器 GPU 报错 0 次。
- 修复旧设置残留后，重启应用仍保持稳定待机；静置期间模拟器 GPU 报错为 0。
- 点击宠物仍会播放回应动画，播完自动回到稳定待机。
- 稳定待机关闭时，同一段持续动画会让模拟器以约每秒 1 次的频率闪黑；真机不受此限制。
- 画面窗外侧（点击区左右两侧）长按不会打开菜单，确认画面窗不拦截鼠标。
- 点击区单击有回应、长按开菜单、拖拽能跟手、丢出和回位正常。
- 点击头顶气泡能收起，不会误触发宠物动作。
- 拖拽、抛掷、边缘反弹、随机走动。
- 长按 / 右键菜单，菜单底边不压任务栏。
- 设置面板滚动到 AI 配置，大小和不透明度即时生效。
- 蓝毛小女仆与小黑鸡坤坤双向切换。
- 重启后恢复宠物种类、透明度和窗口位置。
- 本地文案气泡正常显示。
- 设备通过本地模拟接口请求 AI，气泡显示模型回复。
